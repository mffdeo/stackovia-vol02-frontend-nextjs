    details: "Estado é a memória do componente. Quando o estado muda, o React re-renderiza o componente. O DOM atualiza como consequência — não como causa."
  - title: "Cap. 04 — Next.js App Router"
    details: "Cada pasta com page.tsx vira uma rota; layout.tsx define o wrapper compartilhado; Link mantém o estado da aplicação durante a navegação."
  - title: "Cap. 05 — TypeScript pragmático"
    details: "TypeScript é feedback antecipado: transforma erros de runtime em erros de compilação. any desativa o feedback — é dívida com juros diários."
  - title: "Cap. 06 — Tailwind e shadcn/ui"
    details: "Design tokens como fonte única da verdade visual: cores, espaçamentos e tipografia definidos em um lugar, usados em todo o código."
  - title: "Cap. 07 — Dados mockados e estado assíncrono"
    details: "Dado assíncrono tem 4 estados: loading, error, empty e success. A UI precisa representar cada um deles explicitamente."
  - title: "Cap. 08 — Formulários tipados e validação"
    details: "Validação em tempo real como ajuda ao usuário, não punição. Zod como contrato de dados tipado; React Hook Form como gerenciador de estado."
  - title: "Cap. 09 — Acessibilidade real"
    details: "Acessibilidade não é decoração — é contrato com o usuário. ARIA complementa a semântica nativa quando o HTML não é suficiente."
  - title: "Cap. 10 — Performance web"
    details: "Core Web Vitals medem o que o usuário percebe — carregamento, estabilidade e interatividade. next/image e next/font são as correções de maior impacto."
  - title: "Cap. 11 — Testes com Vitest e Playwright"
    details: "Teste bom verifica o que o usuário vê e faz, não detalhes internos. Se o teste não falha quando o código está errado, não é teste."
  - title: "Cap. 12 — Segurança frontend"
    details: "CORS protege o usuário do browser. CSP instrui o browser a bloquear scripts e recursos não autorizados. Ambos são linhas de defesa, não balas de prata."
  - title: "Cap. 13 — Build, lint e prettier"
    details: "Pipeline local é a primeira linha de qualidade que o desenvolvedor controla. Build, lint e type check antes de commitar evitam surpresas no CI."
  - title: "Cap. 14 — Fechamento do V02"
    details: "Fechamento profissional: métricas reais (Lighthouse, testes verdes, checklist a11y) como portfólio. Honestidade sobre limitações é credibilidade."
